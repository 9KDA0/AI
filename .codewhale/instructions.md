# Context Optimization Rules

> Эти правила управляют тем, как агент структурирует контент в промпте.
> Цель: максимизировать KV-cache hit rate на DeepSeek V4 → снизить стоимость запросов в ~10 раз.

## Порядок контента (KV-cache friendly)

DeepSeek V4 кеширует стабильные префиксы блоками по 128 токенов.

### Стабильное → в начало (не менять между запросами)
- System prompt, Statutes, Regulations
- Инструкции (этот файл, CLAUDE.md)
- Ключевые архитектурные решения

### Изменяемое → в конец (append-only)
- Результаты поиска и чтения файлов
- Текущий план действий (checklist)
- Новые правки и их результаты

### Правила
- **Не переупорядочивай** предыдущие сообщения — ломает prefix cache
- **Не перефразируй** уже процитированный код — ссылайся по пути и строке
- **Append-only**: новый контент добавляется в конец, старый не трогается
- При повторном чтении файла — тот же путь и range → кеш переиспользуется

## Observation Masking

Длинные выводы инструментов сжимать до ключевых фактов:

```
[CM] file: path/to/file.py L120-145 → используется для: <назначение>
[CM] grep: pattern="foo" → 3 совпадения в module_a, module_b
[CM] exit=0, stdout: <ключевая строка>
```

**Не маскировать:** ошибки (stack traces), текущий checklist, файлы перед редактированием.

## Compaction (автоматический)

- `auto_compact = true`, порог = 70%
- Перед compaction: завершить атомарный шаг, сохранить состояние в `note`
- После compaction: перепроверить summary, номера строк для патчей

## Partitioning

Использовать sub-agents когда:
- 3+ независимых подзадач
- Контекст заполнен на 60%+
- Подзадачи не зависят друг от друга последовательно
